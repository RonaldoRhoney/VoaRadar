# Voa Radar v0.2 — UX

## 1. Princípio

A interface deve responder rapidamente: "Para onde posso viajar com meu orçamento?"

## 2. Home

Hero: **Voa Radar** — "Seu radar para viajar pagando menos."

Subtexto: "Diga quanto você pode gastar e descubra para onde pode viajar."

## 3. Busca

Campos: Quanto você quer gastar? / De onde você quer sair? / Quando quer viajar? / Quantas pessoas?

Checkbox: "Não sei para onde ir"

CTA: "Encontrar viagens"

## 4. Experiência de carregamento

Nunca deixar tela aparentemente congelada. Mostrar skeleton + mensagem contextual, ex.: "🔎 Procurando oportunidades para você..."

## 5. Resultados

Cabeçalho: "Encontramos 18 possibilidades."

Subtexto: "Saindo de Belém • Outubro • Até R$ 800"

## 6. Destaque

O primeiro resultado pode ser destacado: "⭐ Melhor oportunidade". Nunca afirmar que é "a melhor do mercado" — significa apenas "melhor resultado segundo os critérios atuais do Voa Radar".

## 7. Filtros

Desktop: sidebar ou toolbar. Mobile: botão "[Filtros]" abrindo bottom sheet.

## 8. Ordenação

Botão "[Ordenar]" com opções: Menor preço, Melhor oportunidade, Menor duração, Menos escalas.

## 9. Feedback

O usuário deve sempre saber: o que está acontecendo, quantos resultados existem, quais critérios foram usados.

## 10. Acessibilidade

Garantir: contraste, labels, foco, navegação por teclado, aria quando necessário, botões semanticamente corretos, textos compreensíveis.

## 11. Mobile

Prioridade máxima. Cards devem ser facilmente escaneáveis. Informações mais importantes, em ordem: destino, preço, oportunidade, data, CTA. Detalhes secundários podem aparecer posteriormente.

## 12. Linguagem

Evitar linguagem técnica. Não "Fare class" → preferir "Tipo de tarifa". Não "IATA" → preferir "Local de partida".

## 13. Personalidade

A interface pode ser amigável e humana — ex.: "✈️ Encontramos destinos que cabem no seu bolso." Mas não deve ser infantil. Deve transmitir: confiança, tecnologia, simplicidade.
